Architecture

A short, honest overview of how VGRE runs machine-learning workloads on CPUs — from the CUDA-on-CPU roots to the in-tree ML stack layered on top.

Python bindings — vgre.LanguageModel, vgre.Tokenizer, and the vgre.nn framework (thin ctypes wrappers over a stable C ABI).
Model layers — transformers, Mamba/SSM, Mixture-of-Experts, LoRA/QLoRA, BitNet ternary, structured sparsity.
Autograd engine — reverse-mode autodiff with op adjoints, AdamW/SGD, gradient checkpointing.
Compute kernels — from-scratch SIMD GEMM (fp32/bf16), attention, conv/pool, quantized codecs, selective scan.
CUDA-on-CPU runtime — CUDA-C compiled through an LLVM JIT and executed on the CPU (the original VGRE core).
Distributed layer — collectives (all-reduce) and tensor/pipeline/expert parallelism over TCP sockets.

CUDA on the CPU

VGRE started as a virtual GPU runtime: it takes CUDA-C, compiles it through an LLVM-based JIT, and executes the resulting kernels on the CPU — no physical GPU involved. This path implements a broad device-intrinsic surface and even supports source-level debugging. It is the "GPU emulator" heritage of the project and lives in the full vgre library.

The machine-learning stack does not require that JIT: the lightweight libvgre_nn library is LLVM-free and self-contained, so training and running models needs only a C++ toolchain.

The compute core: SIMD GEMM

At the bottom of the ML stack is a hand-written, threaded, SIMD matrix-multiply (GEMM) for fp32 and bf16, with dequantize-in-GEMM paths for quantized weights. Every higher-level operation — linear layers, attention, convolutions — is expressed on top of it. There is no dependency on an external BLAS for the lightweight path.

Autograd and optimizers

A reverse-mode automatic-differentiation engine records a graph of operations and computes exact gradients via each op's adjoint. On top of it sit AdamW and SGD, gradient clipping, dropout, a cosine learning-rate schedule, and gradient checkpointing (recompute activations in the backward pass to trade compute for memory). The Python vgre.nn layer exposes this as a familiar, PyTorch-like API.

Model building blocks

  • Transformers — RMSNorm, RoPE, causal multi-head (and flash) attention, SwiGLU/MLP FFNs.
  • Mamba / state-space models — a selective-scan (S6) recurrence that is linear-time and keeps no growing KV cache; usable standalone or interleaved with attention (Jamba-style hybrid stacks).
  • Mixture-of-Experts — a learned top-k router with compute-sparse dispatch, so only a few experts run per token; experts can shard across cluster ranks.
  • Quantization — BitNet b1.58 ternary weights (multiplication-free GEMM), int8/bf16 weight inference, MXFP4 microscaling, and int8/int4 KV-cache quantization.
  • Parameter-efficient fine-tuning — LoRA and QLoRA (a low-bit frozen base plus small trainable adapters), so a large layer can be adapted on a laptop.
  • Decoding — greedy, top-k, nucleus sampling, and lossless / sampler-exact speculative decoding, including multi-token-prediction self-drafting.

Distributed training

VGRE ships a from-scratch collective layer (TCP all-reduce) and executors for data-parallel, tensor-parallel, pipeline-parallel, and expert-parallel training. In vgre.nn, all_reduce_gradients() averages gradients across ranks after backward(), and the differentiable all_reduce op enables tensor/expert parallelism where a single layer is too large for one node.

Honest scope The transport, collectives, and partitioners are built and verified across real OS processes on one machine (bit-identical results, zero cross-step drift). A true run across multiple physical machines, and runs on frontier-scale checkpoints, use the same code paths but have not been demonstrated at that scale here.
