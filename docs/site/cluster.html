Distributed Clusters

Scale kernels across machines over LAN or WAN. Channels are authenticated with HMAC-SHA256, encrypted with AES-256-CTR, and compressed with LZ4.

vgre-start commands

bash
vgre-start --master                              # start a master node (launches dashboard)
vgre-start --worker                              # start a worker (LAN auto-discovery)
vgre-start --worker --is-master                  # headless master (K8s / container mode)
vgre-start --worker --master-ip <IP>             # LAN: connect to a specific master IP
vgre-start --worker --master-address <HOST:PORT> # WAN: hostname, IPv4, or IPv6
vgre-start --test                                # local self-test (master + worker)
vgre-start --port <N>                            # custom TCP port (default 7777)
vgre-start --threads <N>                         # worker thread count (default: auto)

LAN cluster — step by step

1. Install on every node (Installation). 2. Generate the token on the master and 3. distribute it to workers (Token Management). 4. Start the services:

bash
# Master:
vgre-start --master

# Workers (LAN auto-discovery):
vgre-start --worker

# Workers (explicit LAN IP):
vgre-start --worker --master-ip 192.168.1.10

WAN cluster

For workers on a different network, UDP broadcast cannot cross routers — use a direct TCP connection. Three methods:

Method A — explicit IP

bash
# On master: find your public IP
vgre-discover        # -> Public IP: 78.45.12.99  (prints the worker command)

# On worker (any network):
vgre-start --worker --master-address 78.45.12.99:7777

Method B — automated token-keyed discovery

bash
vgre-discover --register     # on master (run once, or after the IP changes)
#   -> Bucket ID: aBcDeFgH   (share this with workers)
vgre-discover --find aBcDeFgH  # on each worker (same token required)
vgre-start --worker --master-address 78.45.12.99:7777

See Public IP Discovery for how the token-keyed KV store works.

Method C — VPN overlay (Tailscale / ZeroTier)

bash
# Both machines on the same Tailscale network; master's Tailscale IP 100.64.0.1
vgre-start --worker --master-ip 100.64.0.1

Firewall rules

bash
# Linux (UFW)
sudo ufw allow 7777/tcp     # TCP cluster
sudo ufw allow 7778/udp     # UDP discovery (LAN only)

# Windows PowerShell (admin)
New-NetFirewallRule -DisplayName "VGRE TCP" -Direction Inbound -Protocol TCP -LocalPort 7777 -Action Allow

Automatic reconnection

Workers reconnect after a master restart or a network drop using exponential backoff:

StateBehavior
Connection dropsRetry immediately, then 1 s → 2 → 4 → … → 120 s
Master restartsWorker reconnects within one backoff cycle
IP changesRe-run vgre-discover --register on master; workers re-run --find

The backoff ceiling is configurable: export VGRE_CLUSTER_MAX_BACKOFF_SEC=60.

Dashboard disconnect detection

The dashboard detects worker disconnections automatically (TCP keepalive, ~12 s after a drop): the node card turns red with a DISCONNECTED countdown, a floating notification appears, and the node is removed from the topology after 30 s — the 3D canvas updates in real time.

Cross-platform support

The wire protocol is OS-agnostic (the CrossPlatform* socket/error/memory tests pass everywhere). Any OS can be master or worker:

MasterWorkerStatus
LinuxLinux / macOS / WindowsFully supported (Linux CI-verified)
