CLI Tools

Every command installed with VGRE, what it does, and how to use it.

install_local.sh links the runtime tools into ~/.local/bin (add it to PATH — the installer does this for you). On Windows the same commands ship as .bat / .ps1 scripts (see the note at the bottom). Every command below prints usage with --help.

Cluster &amp; runtime

CommandWhat it doesCommon usage
vgre-startStart a master or worker node (auto-sources ~/.vgre/env).vgre-start --master · --worker · --worker --master-ip 10.0.0.5 · --worker --port 7778 · --test (master+worker on one box)
vgre-workerThe worker binary itself (usually launched by vgre-start).vgre-worker --version (prints build-info JSON) · --is-master (headless master in containers)
vgre-dashboardLaunch the real-time Flutter monitor (utilization, kernels, cluster, memory, logs).vgre-dashboard
vgre-tokenManage the shared cluster auth token (HMAC-SHA256 / AES-256-CTR channels).vgre-token generate · fingerprint · set <TOKEN> · copy · push user@HOST
vgre-discoverPublic-IP discovery + token-keyed cross-LAN registration (find a master over WAN).vgre-discover (show public IP) · --set-master · --register · --find · --unregister
vgre-connect-checkVerify WAN/LAN connectivity to a master before starting a worker.vgre-connect-check <master-ip> [port]

Cluster quick recipes

bash
# One machine — spin up a master + worker and self-test:
vgre-start --test

# Master node:
vgre-token generate           # create the shared token (prints its fingerprint)
vgre-token copy               # prints the scp command to share it with workers
vgre-start --master           # starts the master + dashboard

# Worker node (after receiving the token):
vgre-token set <TOKEN>        # or: vgre-token push user@worker  (from the master)
vgre-connect-check 10.0.0.5   # confirm reachability first
vgre-start --worker --master-ip 10.0.0.5

Developer tools

Built binaries land in build/tools/ (run them from there, or add it to PATH):

CommandWhat it doesCommon usage
vgre_ptx_gdbserverServe a PTX kernel to a stock gdb for source-level step debugging (CUDA-GDB-style, no GPU).vgre_ptx_gdbserver kernel.ptx then gdb → target remote :1234 (see Debugging PTX)
gpt2_inferReal GPT-2 inference from a safetensors / GGUF checkpoint (matches Hugging Face bit-for-bit).gpt2_infer model.safetensors --gen "Hello"

Setup helpers

ScriptWhat it does
install_local.shOne-command Linux/macOS install: deps, build, ~/.vgre/env, auth token, CLI symlinks.
scripts/vgre-cli-install.sh(Re)install the CLI symlinks and ensure ~/.local/bin is on PATH.
scripts/vgre_sync.shRefresh ~/.vgre/env and re-link the CLIs after a rebuild.
scripts/vgre-mac-worker-setup.shmacOS worker bring-up (launchd, DYLD paths).
scripts/vgre-print-linux-setup.shLinux desktop-launcher / print setup for the dashboard.
Tip

Windows: the same commands ship as scripts under scripts\ — vgre-start.bat, vgre-token.bat / vgre-token.ps1, vgre-discover.bat / .ps1, plus PowerShell installers Install-VGRETools.ps1, Setup-VGRECluster.ps1, and Start-VGRE.ps1. Env vars are set in User scope by vgre_sync.bat / vgre_env.ps1.
