Token Management

vgre-token manages the shared 256-bit cluster auth token — the secret that authenticates every node. It works from any directory on all three platforms.

Commands

bash
vgre-token generate       # generate a new secure 256-bit token
vgre-token show           # print the stored token value
vgre-token fingerprint    # print the SHA-256 fingerprint
vgre-token set [TOKEN]    # store a token pasted from another machine
vgre-token verify         # check the env var matches the stored file
vgre-token copy           # print the scp / robocopy command for workers
vgre-token revoke         # delete the stored token (with confirmation)
vgre-token install        # install vgre-token to the User PATH (first run)

Typical workflow

bash
# ── On the MASTER machine ─────────────────────────────────────
vgre-token generate
#   Token saved to ~/.vgre/token
#   Token fingerprint (SHA-256): a3f9bcd2...

# Share the token with workers (pick one):
vgre-token copy                      # prints the scp / robocopy command
scp ~/.vgre/token worker@192.168.1.50:~/.vgre/token

# ── On every WORKER machine ───────────────────────────────────
vgre-token set a3f9bcd2xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx  # option B: paste the value

# ── Verify both machines match ────────────────────────────────
vgre-token fingerprint               # run on BOTH — the output must be identical

Token storage

PlatformToken fileEnv var set in
Linux / macOS~/.vgre/token (chmod 600)~/.vgre/env → shell profile
Windows%USERPROFILE%\.vgre\tokenUser-scope env (no restart needed)
Tip

The token never travels over the network — only its HMAC-SHA256 challenge does. Distribute the file over a secure channel (scp) or paste the value directly; the fingerprint lets you confirm a match without revealing the secret.
