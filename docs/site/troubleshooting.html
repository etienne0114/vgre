Troubleshooting

Fixes for the issues you are most likely to hit, by symptom.

Dashboard fails to load ("Failed to load native library")

bash
source ~/.vgre/env
ls -la ~/.local/share/VGRE/lib/libvgre.so
ldd ~/.local/share/VGRE/lib/libvgre.so | grep "not found"
sudo apt-get install libomp-dev        # if libomp.so is missing

vgre-start not recognised (Windows)

powershell
Test-Path "$env:LOCALAPPDATA\VGRE\scripts\vgre-start.bat"
$env:PATH = "$env:LOCALAPPDATA\VGRE\scripts;$env:PATH"   # if PATH not yet updated
vgre-start --help
.\scripts\vgre_sync.bat                                    # reinstall

Worker cannot connect to master

bash
vgre-token fingerprint                       # 1. run on BOTH — must be identical
nc -zv MASTER_IP 7777                        # 2. test reachability (Linux/macOS)
Test-NetConnection MASTER_IP -Port 7777      #    (Windows PowerShell)
sudo ufw allow 7777/tcp                      # 3. open the firewall (Linux)
vgre-discover                                # 4. WAN: verify the public IP
export VGRE_CLUSTER_CONNECT_TIMEOUT_SEC=30   # 5. raise the timeout on slow links

UDP auto-discovery not working across subnets

UDP broadcast (255.255.255.255) cannot cross routers. Use a direct connection or token-keyed discovery instead:

bash
vgre-start --worker --master-ip 192.168.1.10           # same LAN, different subnet
vgre-start --worker --master-address 78.45.12.99:7777  # WAN / internet
vgre-discover --register   # on master
vgre-discover --find <ID>  # on worker

Mismatched token fingerprints

bash
vgre-token copy          # on master — prints the scp command
scp ~/.vgre/token worker@WORKER_IP:~/.vgre/token
vgre-token fingerprint   # verify on both machines

CMake cannot find LLVM

bash
# Linux
sudo apt-get install llvm-18 llvm-18-dev clang-18
export LLVM_DIR=$(llvm-config-18 --cmakedir)

# macOS (CMake auto-detects; override only if needed)
brew install llvm@18 libomp
export LLVM_DIR="$(brew --prefix llvm@18)/lib/cmake/llvm"

# Windows
winget install LLVM.LLVM
set LLVM_DIR=C:\Program Files\LLVM\lib\cmake\llvm
Tip

Or skip LLVM entirely: cmake -S . -B build -DVGRE_ENABLE_JIT=OFF builds with just a C++17 compiler.

Flutter build fails (Windows)

powershell
.\scripts\vgre_sync.bat            # re-run — it pre-caches engine artifacts

flutter precache --windows         # or, manually:
cd vgre_dashboard
flutter pub get
flutter build windows --release

Low compute performance

SIMD is auto-detected at configure time. Confirm which level was selected, or force one:

bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release 2>&1 | grep -i "simd\|avx\|amx"
export VGRE_SIMD_LEVEL=AVX512        # force a level at runtime
VGRE_LOG_LEVEL=DEBUG ./build/examples/matrix_multiply 2>&1 | grep "SIMD\|AVX\|AMX"

OpenMP not working (all kernels run on one thread)

bash
ldd ~/.local/share/VGRE/lib/libvgre.so | grep omp
sudo apt-get install libomp-dev        # Ubuntu/Debian
sudo dnf install libomp-devel          # Fedora
# macOS: brew install llvm@18 libomp && rm -f build/CMakeCache.txt && cmake -B build

Windows: DLL load failure (0xC000001D / error 1114)

powershell
dumpbin /dependents $env:LOCALAPPDATA\VGRE\vgre.dll
Get-ChildItem "$env:LOCALAPPDATA\VGRE\lib" -Filter "*.dll" | Select-Object Name
.\scripts\vgre_sync.bat            # re-run to restore missing DLLs

Windows: socket / port-bind failures (ACCESS_VIOLATION 0xC0000005)

These are handled inside the runtime; if a custom integration hits them:

  • WSAStartup lifecycle (WinSock 10093) — VGRE manages WSAStartup/WSACleanup with a thread-safe WindowsSocketManager (Meyers singletons + std::call_once); ensure no external library closes WinSock early.
  • Struct packing — all cross-platform packet headers use #pragma pack(push, 1) / __attribute__((packed)) for bit-identical layout across MSVC and GCC/Clang.
  • Port conflicts (TIME_WAIT) — set VGRE_PORT to a free port or raise VGRE_CLUSTER_CONNECT_TIMEOUT_SEC.
