Train and run ML models on CPUs — from scratch, no GPU

VGRE is a lightweight, from-scratch runtime for training and running neural networks entirely on ordinary CPUs. No GPU, no CUDA hardware, and no external machine-learning framework — the tensor engine, autograd, optimizers, transformer, Mamba, and quantization stacks are all in-tree.

Get started How it works

What VGRE is

VGRE (Virtual GPU Runtime Engine) began as a CPU-based emulator for CUDA and grew a complete, dependency-free machine-learning stack on top of it. You can:

  • Train a small language model or an arbitrary network from Python with a PyTorch-like API.
  • Run autoregressive text generation with greedy, top-k, top-p, and speculative decoding.
  • Use modern building blocks — transformers, Mixture-of-Experts, Mamba/SSM, LoRA/QLoRA, BitNet ternary quantization — implemented from scratch on a CPU SIMD GEMM.
  • Distribute training across processes over TCP (data-, tensor-, and expert-parallel).

No GPU required

Everything runs on the CPU. The core ML library (libvgre_nn) is LLVM-free and carries essentially no heavy dependencies.

From scratch

SIMD GEMM, reverse-mode autograd, AdamW/SGD, a byte-level BPE tokenizer, and the model layers are all in-tree — no BLAS or ML framework needed for the light path.

Python-first

Import vgre, build a LanguageModel or compose layers with vgre.nn, then train and generate — a small, familiar surface.

Serveable

A minimal HTTP inference server, a Dockerfile, and a fly.io config make it easy to put a trained model behind an endpoint.

Who it's for

  • Researchers and engineers who want to understand or modify a full ML stack without a GPU.
  • People experimenting with quantization, MoE, SSMs, or distributed training on commodity CPUs.
  • Anyone who wants to train and serve a small model on a laptop or a plain server, offline.

Current status — read this first

VGRE is an advanced technical prototype, not a production system. Know what is and isn't demonstrated before relying on it.

Verified end-to-end today:

  • Real GPT-2 (124M) inference matching Hugging Face token-for-token.
  • Small in-tree models that train to convergence and generate correctly.
  • Multi-process distributed training over real sockets (data-, tensor-, and expert-parallel) on a single machine across separate OS processes.

Architecturally supported but not yet demonstrated at scale:

  • Frontier-scale checkpoints (e.g. Llama-3 70B/405B) — the same code path as the demonstrated GPT-2 run, but a real large run needs a license-gated multi-GB download.
  • True multi-machine cluster runs across a physical network — the transport, collectives, and partitioner are built and tested across processes, but not across real machines here.

There are no production-scale performance benchmarks published here, and this site does not claim any. Treat throughput and memory figures as things to measure on your own hardware.
