Quickstart

Build the native library, install the Python bindings, train a tiny language model, generate text, and stand up the HTTP inference server — all on CPU.

Prerequisites A C++ toolchain and CMake, Python 3.8+, and NumPy. The lightweight ML library (libvgre_nn) is LLVM-free, so you do not need LLVM for the ML path.

1.Build the native library

Clone the repository and build the LLVM-free vgre_nn target. This produces the shared library the Python bindings load.

git clone https://github.com/etienne0114/vgre
cd vgre

cmake -S . -B build
cmake --build build --target vgre_nn
# → build/src/xla/libvgre_nn.so

The bindings can also load the full vgre library (which additionally provides the CUDA-on-CPU runtime and needs LLVM); for training and running models, vgre_nn is all you need.

2.Install the Python bindings

Install the vgre package (pure-Python ctypes wrappers) and point it at the library you just built:

pip install ./bindings/python        # or: pip install -e ./bindings/python

# Tell the bindings where the native library is:
export VGRE_LIB_PATH="$PWD/build/src/xla/libvgre_nn.so"

Prefer not to install? Use the source tree directly:

export PYTHONPATH="$PWD/bindings/python:$PYTHONPATH"
export VGRE_LIB_PATH="$PWD/build/src/xla/libvgre_nn.so"

Verify:

python -c "import vgre; print('native available:', vgre.NATIVE_AVAILABLE)"

If VGRE_LIB_PATH is unset, the loader also searches ./build, ./build/lib, and the package's bundled lib/ directory.

3.Train a tiny model and generate

This trains a small Llama-style decoder on any plain-text file, then samples from it. Everything runs on the CPU.

import vgre

# 1. Train a byte-level BPE tokenizer on your corpus.
text = open("input.txt").read()            # any plain-text file
tok  = vgre.Tokenizer().train(text, num_merges=512)
ids  = tok.encode(text)

# 2. Build a small decoder LM (RMSNorm, RoPE, causal attention, SwiGLU).
lm = vgre.LanguageModel(
    vocab=tok.vocab_size,
    n_layer=4, d_model=256, n_head=8,
    max_seq=128, seed=1234,
)
print("parameters:", lm.num_parameters)

# 3. Train on sliding windows (predict each token from the previous ones).
seq_len = 64
for step in range(2000):
    i = (step * seq_len) % (len(ids) - seq_len - 1)
    window  = ids[i : i + seq_len]
    targets = ids[i + 1 : i + seq_len + 1]
    lr = vgre.cosine_lr(step, warmup=100, total=2000, base_lr=3e-3, min_lr=3e-4)
    loss = lm.train_step(window, targets, lr)
    if step % 200 == 0:
        print(f"step {step:4d}  loss {loss:.3f}")

# 4. Generate text (greedy if temperature<=0; else top-k / nucleus sampling).
prompt = tok.encode("The ")
out    = lm.generate(prompt, n_new=60, temperature=0.8, top_k=40, top_p=0.95)
print(tok.decode(out))

# 5. Persist the model.
lm.save("model.vgre")

See the API reference for every argument, the mini-batch train_batch path, quantized inference (set_bf16_inference, set_int8_inference, KV-cache quantization), and the vgre.nn framework for building arbitrary networks.

4.Run the HTTP inference server

The server loads a saved model and exposes a small JSON API. Start it with:

python server/vgre_server.py
# listens on http://localhost:8000 by default

Endpoints

Method & pathDescription
GET /healthLiveness check. Returns a small JSON status object.
GET /infoModel / server metadata (e.g. model configuration).
POST /generateGenerate text. JSON body: {"prompt": <string>, "max_tokens": <int>, "temperature": <float>}.

Example requests

# Health and info
curl -s http://localhost:8000/health
curl -s http://localhost:8000/info

# Generate
curl -s -X POST http://localhost:8000/generate \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "The ", "max_tokens": 60, "temperature": 0.8}'
