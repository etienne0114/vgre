Debugging PTX with GDB

CUDA-GDB-style single-stepping through PTX kernels using a stock gdb — no GPU, no cuda-gdb install.

How it works

VGRE ships a PTX single-step interpreter and a GDB remote-serial-protocol server. Each CUDA thread appears as a GDB thread (a lane); the kernel's own virtual PTX registers are exposed to info registers; and breakpoints, stepi, and memory inspection all behave normally in an unmodified gdb.

Start the stub

vgre_ptx_gdbserver kernel.ptx saxpy 1 4 2000 \
    f32:2.0 buf:f32:4=1,2,3,4 buf:f32:4=10,20,30,40 u32:4
# prints the instruction listing, buffer addresses, and:
#   gdb remote stub listening on 127.0.0.1:2000

Attach a normal gdb

gdb -ex 'target remote 127.0.0.1:2000'
(gdb) info threads          # CUDA lanes of the running CTA
(gdb) break *0x12           # breakpoint by instruction index
(gdb) continue
(gdb) info registers ptx_f4 rip
(gdb) stepi
(gdb) x/4fw 0x...           # read global memory
Tip

The interpreter covers the arithmetic/control/memory core nvcc emits for compute kernels, with bar.sync-aware lane scheduling. Verified end-to-end against a real gdb 15 client.
