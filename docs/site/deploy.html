Deploy

Package the VGRE inference server as a container and run it anywhere, or deploy it to fly.io with a single command. CPU-only — no GPU node required.

What you are deploying The HTTP inference server from the Quickstart: GET /health, GET /info, and POST /generate. Train and save a model first, then serve it.

Docker

A Dockerfile at the repository root builds an image that runs the server. Build and run it:

docker build -t vgre-server .

docker run --rm -p 8000:8000 vgre-server

Then hit the endpoints exactly as in the Quickstart:

curl -s http://localhost:8000/health

curl -s -X POST http://localhost:8000/generate \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "The ", "max_tokens": 60, "temperature": 0.8}'

To serve your own trained checkpoint, make the model file available to the container (for example by mounting a volume) and point the server at it. Because everything runs on CPU, the image needs no GPU runtime and no special host drivers.

fly.io

A fly.toml at the repository root describes the app (CPU VM, the internal service port, and a health check on /health). Deploy with the Fly CLI:

# One-time: install flyctl and sign in
fly auth login

# First deploy also creates the app if it does not exist
fly deploy

fly deploy builds the image (from the same Dockerfile), pushes it, and rolls it out. Use fly logs to watch startup and fly status to check health. Scale CPU/memory in fly.toml or with fly scale.

Continuous deployment

The repository's CI can deploy automatically. When a FLY_API_TOKEN secret is present in the repository settings, the deploy workflow runs fly deploy on qualifying pushes. Without that secret the step is skipped, so forks and PRs never attempt a deploy.

# Create a deploy token locally, then add it as a GitHub Actions secret:
fly tokens create deploy
# GitHub → Settings → Secrets and variables → Actions → New secret
#   Name:  FLY_API_TOKEN
#   Value:

Notes on scale

  • Inference speed and memory depend entirely on the CPU and the model size — measure on your target hardware. This project publishes no throughput benchmarks.
  • For smaller footprints, enable quantized inference before serving (set_bf16_inference / set_int8_inference, and KV-cache quantization) and call drop_fp32_weights() once the model is serve-only. See the API reference.
