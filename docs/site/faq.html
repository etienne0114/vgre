Frequently Asked Questions

Does VGRE need a GPU?

No. That is the point — kernels execute on the CPU. A GPU is never required.

Is it as fast as a real GPU?

No. Expect 10–50× slower for compute-bound kernels; memory-bound kernels are closer with AVX-512. VGRE targets learning, CI, development, and moderate workloads — not latency-critical production inference.

Which platforms are supported?

All three are CI-green. The full ctest suite passes on Linux x86-64 (399 tests with LLVM, 379 in the LLVM-free build — the required CI job), on macOS (Apple Silicon, auto-detected Homebrew llvm@18), and on Windows (clang-cl on windows-2022). Linux ARM64 builds and tests via NEON. Prebuilt wheels ship for Linux, macOS (arm64) and Windows — see Downloads.

macOS: OpenMP or JIT failures?

  • Install brew install llvm@18 libomp and reconfigure: rm -f build/CMakeCache.txt && cmake -B build.
  • Ensure Clang is discoverable: export PATH="$(brew --prefix llvm@18)/bin:$PATH" or export VGRE_CLANG_PATH=$(brew --prefix llvm@18)/bin/clang++.
  • Run tests serially: ctest -j1 --timeout 300.

The dashboard won't start / can't find the library.

  • Rebuild and reinstall, then open a new terminal so ~/.vgre/env is loaded.
  • Check library path: Linux LD_LIBRARY_PATH, macOS DYLD_LIBRARY_PATH — both set in ~/.vgre/env after install.
  • Check VGRE_LIB_PATH points to a real libvgre.so / libvgre.dylib / vgre.dll.
  • Windows: ensure %LOCALAPPDATA%\VGRE and ...\VGRE\lib are on PATH.

A CUDA call returns an error.

VGRE implements ~95% of common CUDA APIs and returns a clear error for the rest rather than misbehaving. File an issue with the failing call and we can prioritize it.
