API Reference

Python, C ABI, and the CUDA-runtime shim.

Python bindings

The vgre package wraps the native library via ctypes:

SymbolPurpose
vgre.TokenizerBPE tokenizer; train, load_hf, encode, decode.
vgre.LanguageModelIn-tree GPT; train, generate, save, load.
vgre.nn.LoRALinearLow-rank adapters; adapter_parameters, merge.
vgre.vector.VectorIndexHNSW ANN; add, search, save, load.

C ABI (vgre_c_api.h)

The stable C surface the wheel and dashboard bind to. Highlights:

c++
vgre_init();
vgre_set_profiler_enabled(1);
vgre_set_block_threads(0);
vgre_get_memory_bandwidth_stats(&stats);
// tokenizer
vgre_bpe* t = vgre_bpe_create();
vgre_bpe_load_hf(t, "tokenizer.json");
int n = vgre_bpe_encode(t, "hi", ids, 256);

CUDA runtime shim (libvgre_cudart)

Drop-in libcudart replacement covering ~95% of the common CUDA Runtime + Driver API (memory, streams, events, graphs, textures, cooperative launch) plus the cuBLAS / cuDNN / cuFFT / cuRAND / cuSOLVER / cuSPARSE / NCCL shims. Preload it (Linux LD_PRELOAD, macOS DYLD_INSERT_LIBRARIES) to route an existing CUDA binary's cuda* calls into VGRE — no source changes.

Dashboard telemetry

The dashboard polls a JSON telemetry schema; the top-level groups are:

GroupFields
utilizationsm / memory / pcie percentages, sampled over time
kernelsname, grid/block dims, launch count, total & average time, tier
memoryallocations, pools, free/used bytes, bandwidth & est. GPU speedup
clusterper-node id, OS/arch/hostname, in-flight & cumulative kernels, secure-channel state
logsthe last N log messages at the active VGRE_LOG_LEVEL
