Public IP Discovery

vgre-discover solves the WAN bootstrap problem — finding the master's real public IP and handing it to workers without manual configuration.

Commands

bash
vgre-discover                  # show the real public IP + worker connect command
vgre-discover --set-master     # set VGRE_CLUSTER_ADVERTISED_ADDRESS for this session
vgre-discover --register       # register the master IP to a token-keyed KV store
vgre-discover --find [BUCKET]  # (worker) retrieve the master IP using the local token
vgre-discover --unregister     # remove the registration from the KV store

How it works

Public IP detection tries five HTTP endpoints in order and uses the first valid IPv4 response: api.ipify.org, ipecho.net/plain, icanhazip.com, checkip.amazonaws.com, api4.my-ip.io/ip.

Master auto-broadcast — vgre-start --master calls vgre-discover --set-master first, setting VGRE_CLUSTER_ADVERTISED_ADDRESS=<public-ip>:7777. The UDP announcer embeds that real address in every broadcast so workers behind NAT receive the correct IP instead of the sender's internal one.

Cross-LAN token-keyed discovery derives the KV-store key from the token:

text
key = "vgre-" + first_32_hex_chars_of( SHA256(token) )

Only nodes holding the same token can compute or look up the same key. The bucket ID is a non-secret opaque identifier shared once with workers — like a meeting-room ID, not a password.

Quick start: WAN cluster with automated discovery

bash
# ── Master ────────────────────────────────────────────────────
vgre-token generate            # if not already done
vgre-discover --register       # prints the BUCKET_ID to share
#   [OK] Master registered.  Bucket ID: aBcDeFgH   Master IP: 78.45.12.99:7777
vgre-start --master            # auto-detects IP and sets the advertised address

# ── Workers (any network, same token) ─────────────────────────
vgre-discover --find aBcDeFgH  # -> Master found: 78.45.12.99:7777
vgre-start --worker --master-address 78.45.12.99:7777

Discovery modes: LAN vs WAN

ScenarioHow discovery works
Same LANUDP broadcast — automatic, no configuration
Different LAN, same tokenvgre-discover --register → --find
Different LAN, manualvgre-discover shows the IP → share the one-liner
VPN (Tailscale / ZeroTier)Same as LAN — auto-discovery works
Dynamic IP (home ISP)Re-run vgre-discover --register after the IP changes
Warning

vgre-discover finds your external IP, but workers can only reach the master if your router port-forwards TCP 7777, or you use a VPN (Tailscale / ZeroTier — no port-forward needed), or the master runs on a VPS / cloud VM with a direct public IP.
